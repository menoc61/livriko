Deployment Overview

This guide covers the different methods available for deploying the Livriko Backend API to a production environment. Choose the method that best fits your hosting infrastructure, budget, and technical expertise.

Deployment Options

Livriko supports four deployment methods. Select the one that matches your hosting setup.

cPanel GUI

Upload files via cPanel File Manager and use the web-based installer. The simplest method with no command-line access required.

Easy

cPanel CLI

Deploy via SSH using Git and Composer. Faster than the GUI method and gives more control over the installation process.

Intermediate

VPS Apache (LAMP)

Full VPS deployment with Apache, MySQL, and PHP. A complete LAMP stack setup for maximum compatibility.

Intermediate

VPS Nginx (LEMP) ⭐

Recommended for production. Nginx with PHP-FPM provides better performance, lower memory usage, and superior concurrency handling.

Recommended

Pre-Deployment Checklist

Complete this checklist before deploying to production. Missing any item may cause deployment failures or security vulnerabilities.

Complete Local Installation & Testing

Ensure the Backend API is fully installed and working locally. Verify you can access the admin panel, create rides, and all features function correctly before deploying.

Prepare a Domain Name

Have a domain name ready (e.g., api.yourdomain.com). Point the domain's A record to your server's IP address using your DNS provider's dashboard.

Gather All Credentials

Have your server SSH credentials, MySQL database credentials, Firebase project credentials, and payment gateway API keys ready before starting.

Prepare Production .env Values

Prepare production-safe values for your .env file: set APP_DEBUG=false, configure the production APP_URL, and use strong database passwords.

Disable Debug Mode

Set APP_DEBUG=false in production. Debug mode exposes sensitive environment variables and stack traces to users, which is a serious security risk.

Security Warning
Never deploy with APP_DEBUG=true in production. This exposes your application encryption key, database credentials, and API keys to anyone who triggers an error page.

Production .env Template

Use this template as a starting point for your production .env configuration. Replace all placeholder values with your actual credentials.

# =============================================
# APPLICATION SETTINGS (Production)
# =============================================
APP_NAME=Livriko
APP_ENV=production
APP_KEY=base64:YOUR_GENERATED_KEY
APP_DEBUG=false
APP_URL=https://yourdomain.com

# =============================================
# DATABASE
# =============================================
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=livriko_db
DB_USERNAME=livriko_user
DB_PASSWORD=your_strong_password

# =============================================
# CACHE & QUEUE (Redis recommended)
# =============================================
BROADCAST_DRIVER=redis
CACHE_DRIVER=redis
QUEUE_CONNECTION=redis
SESSION_DRIVER=redis
SESSION_LIFETIME=120

REDIS_HOST=127.0.0.1
REDIS_PASSWORD=null
REDIS_PORT=6379

# =============================================
# MAIL
# =============================================
MAIL_MAILER=smtp
MAIL_HOST=smtp.mailgun.org
MAIL_PORT=587
MAIL_USERNAME=your_mail_username
MAIL_PASSWORD=your_mail_password
MAIL_ENCRYPTION=tls
MAIL_FROM_ADDRESS="noreply@yourdomain.com"
MAIL_FROM_NAME="${APP_NAME}"

# =============================================
# FIREBASE
# =============================================
FIREBASE_PROJECT_ID=your-project-id
FIREBASE_CREDENTIALS=firebase_credentials.json

# =============================================
# REVERB (WebSockets)
# =============================================
REVERB_APP_KEY=your-reverb-key
REVERB_APP_SECRET=your-reverb-secret
REVERB_APP_ID=your-reverb-app-id
REVERB_HOST=yourdomain.com
REVERB_PORT=443
REVERB_SCHEME=https

SSL Configuration

HTTPS is mandatory for production deployments. Mobile apps communicating with your API require a valid SSL certificate. Use Let's Encrypt (via Certbot) for free, auto-renewing certificates.

SSL Setup
The VPS deployment guides (Apache, Nginx) include complete SSL setup with Certbot. For cPanel, use the built-in SSL/TLS wizard or AutoSSL feature.

Domain Configuration

Before deploying, ensure your domain's DNS records point to your server:

DNS RecordHostValueTTL
A@ (or api)Your server IP address3600
CNAMEwwwyourdomain.com3600
DNS Propagation
DNS changes can take up to 48 hours to propagate globally, though most updates take effect within 1–4 hours. You can check propagation status at dnschecker.org.

Post-Deployment Checklist

After deploying, verify the following items to ensure your production environment is fully operational:

SSL Certificate Active

Verify the HTTPS lock icon appears in your browser. All API traffic must be encrypted.

Admin Panel Accessible

Log in to the admin panel and verify all settings, drivers, and ride data are accessible.

Queue Worker Running

Verify background jobs are being processed. Check Supervisor status or queue worker logs.

WebSockets Connected

Test real-time features like ride status updates and driver location pings.

Mobile Apps Connected

Verify both the User App and Driver App can connect to the production API endpoint.
