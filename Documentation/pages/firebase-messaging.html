Firebase Cloud Messaging

Firebase Cloud Messaging (FCM) is used by Livriko to deliver push notifications to both the User and Driver apps in real time.

FCM Setup Overview

FCM is enabled by default when you create a Firebase project. No additional configuration is needed beyond connecting Firebase to your apps and the admin panel.

Configuring the Server Key

To configure the server key in the admin panel:

Get Server Key

Go to Firebase Console → Project Settings → Cloud Messaging

Copy Server Key

Copy the Server key value from the Cloud Messaging settings.

Paste in Admin Panel

In the Livriko admin panel, navigate to Settings → Firebase and paste the server key in the FCM Server Key field.

Save Settings

Click Save to apply the configuration. Clear config cache if needed.

FCM Token Generation

When users open the Livriko apps, FCM generates a unique token for each device. This token is used to target notifications to specific devices.

// Token registration flow (handled automatically by Livriko apps):
1. App starts and requests notification permission
2. Firebase generates a unique FCM token
3. Token is sent to the Laravel backend via API
4. Token is stored in the user's Firestore document
5. Backend uses the token to send targeted notifications
Token Refresh

FCM tokens can change when the app is reinstalled, the device is factory reset, or the token is refreshed by Firebase. The Livriko apps automatically handle token refresh and update the backend.

Sending Notifications

Livriko supports three notification targeting methods:

1. Device-Based (Single Device)

// Send to a specific device using its FCM token
$messaging->send([
    'token' => 'device-fcm-token-here',
    'notification' => [
        'title' => 'Ride Confirmed',
        'body' => 'Your ride has been confirmed. Driver is on the way.',
    ],
    'data' => [
        'ride_id' => '12345',
        'type' => 'ride_confirmed',
    ],
]);

2. Topic-Based (All Subscribers)

// Send to all devices subscribed to a topic
$messaging->send([
    'topic' => 'promotions',
    'notification' => [
        'title' => 'Weekend Special!',
        'body' => 'Get 20% off all rides this weekend.',
    ],
]);

3. Condition-Based (Multiple Topics)

// Send to devices matching a condition
$messaging->send([
    'condition' => "'riders' in topics || 'drivers' in topics",
    'notification' => [
        'title' => 'System Update',
        'body' => 'Livriko will be under maintenance tonight.',
    ],
]);

Notification Payload Structure

FCM supports two payload types:

Payload Type Behavior Use Case
Notification Payload System tray notification, handled by OS Simple messages shown when app is in background
Data Payload Custom data, handled by app code Ride updates, deep links, custom UI actions
Best Practice

Livriko uses data-only payloads for most notifications. This gives the app full control over notification display and handling, including foreground delivery and custom actions.

Handling Notifications

Foreground (App Open)

When the app is open, notifications are intercepted by the app code and displayed as in-app banners:

// Livriko handles foreground notifications automatically
// App displays an in-app banner and processes the data payload
// User can tap the banner to navigate to the relevant screen

Background (App Closed)

When the app is closed, notifications are handled by the OS and shown in the notification tray. Tapping opens the app at the relevant screen.

Notification Channels (Android)

Android 8.0+ uses notification channels to let users control notification preferences:

Channel Priority Use Case
Ride Updates High Ride status changes, driver arrivals, ride completion
Messages High Chat messages from riders/drivers
Promotions Low Discount offers and promotional messages
System Default Account updates, system announcements

Badge Count (iOS)

iOS displays a badge count on the app icon. Livriko automatically manages the badge count based on unread notifications:

  • Badge increments when a new notification arrives
  • Badge resets to 0 when the user opens the app
  • Badge can be set via the badge field in the FCM payload

Testing Push Notifications

Use the Livriko admin panel to send test notifications:

Open Push Notifications

Navigate to Management → Push Notifications in the admin panel.

Create Notification

Enter the notification title, body, and select the target audience (riders, drivers, or all).

Send Test

Click "Send Test" to deliver the notification to a specific device or user.

Permission Required

Users must grant notification permissions on their device for push notifications to work. On Android 13+, this requires a runtime permission request. On iOS, this is handled during app installation.
