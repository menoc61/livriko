Zones

Zones define the geographical areas where your Livriko ride-hailing, rental, and parcel delivery services operate. Each zone represents a city or region where riders request rides, drivers accept trips, and parcels are delivered. Configuring zones is the first step in setting up your platform.

Prerequisites

Before creating zones, ensure the following are in place.

Google Maps API Key Required
Zone creation relies on Google Maps for drawing boundaries on the map. You must have a valid Google Maps JavaScript API key configured in your platform settings. Without it, the map widget will not render and you will be unable to draw zone polygons.
  • Google Maps API Key — Enable the Maps JavaScript API and Geocoding API in your Google Cloud Console.
  • Admin Panel Access — You need administrator privileges to create or edit zones.
  • Currency Configured — At least one currency must be set up under Platform Settings → Currencies.
  • Zone Boundaries Known — Have the approximate coordinates or a reference map of the area you intend to serve.

Creating a Zone

Follow these steps to add a new geographic service area to your platform.

1. Navigate to Zone Management

Log in to the admin panel. From the left sidebar, go to Livriko Management → Zones. You will see a list of existing zones (empty if this is your first one).

2. Click "Add New Zone"

Click the Add New Zone button in the top-right corner of the zones list page. This opens the zone creation form.

3. Fill In Zone Details

Enter the zone name (e.g., "Paris", "New York City", "Mumbai"), configure the distance measurement type, currency, and payment method. See the field reference table below for full details.

4. Draw the Zone Boundary

Use the interactive map widget to draw the zone boundary. Click on the map to place vertices (points) that define the polygon shape. Connect the last point back to the first to close the polygon. The area inside the polygon is your service area.

5. Enable the Zone

Set the Status toggle to Active. Inactive zones are hidden from riders and drivers and cannot receive ride requests.

6. Save and Verify

Click Save. After saving, verify the zone appears in the list with the correct status. Open the zone to confirm the drawn boundary is accurate on the map.

Field Reference

Complete reference for every field on the zone creation form.

Field Type Required Description
Zone Name Text Yes Display name for the zone shown to riders and drivers (e.g., "Paris", "Lagos Central"). Must be unique across the platform.
Distance Type Dropdown Yes Unit of distance measurement. Choose between Kilometers (km) or Miles. This affects all distance-based fare calculations within the zone.
Currency Dropdown Yes The currency used for fares, coupons, and pricing in this zone. Must match a currency configured under Platform Settings → Currencies (e.g., EUR, USD, NGN).
Payment Method Multi-select Yes Accepted payment methods in this zone. Options include Cash, Card (Stripe), PayPal, Wallet, and other gateways you have configured. At least one must be selected.
Place Points Map polygon Yes The geographic boundary of the zone. Click on the map to place points (vertices) that form a polygon. The enclosed area defines where rides can be requested and accepted.
Map Widget Yes Interactive Google Maps widget for drawing and previewing the zone boundary. Supports zoom, pan, and vertex editing after initial drawing.
Status Toggle Yes Set to Active to make the zone live and visible to riders/drivers. Inactive zones are hidden and cannot receive ride requests.

Zone Features

Once a zone is created, you can configure additional features for each zone.

Availability Areas

Define specific pickup and dropoff sub-areas within the zone where the service is available. Useful for restricting service to certain neighborhoods or districts.

Pricing Per Zone

Set unique base fare, per-km, per-minute, and minimum fare rates for each vehicle type within the zone. See Vehicle Zone Pricing for details.

Surge Pricing

Configure demand-based pricing multipliers that activate automatically during peak hours or high-demand periods within the zone.

Service Restrictions

Limit which vehicle types and services (Ride, Rental, Parcel, Freight) are available in the zone. Not all vehicle types need to operate in every zone.

OpenStreetMap (OSM) Alternative

If you prefer not to use Google Maps, Livriko supports OpenStreetMap via Leaflet.js for zone drawing.

Configuring OSM

  1. Navigate to Platform Settings → Settings → Map Provider.
  2. Change the map provider from Google Maps to OpenStreetMap.
  3. Save the settings. The zone creation map widget will now use Leaflet.js and OSM tiles.
No API Key Needed
OpenStreetMap does not require an API key, making it a cost-effective choice for development and testing. However, Google Maps is recommended for production due to superior geocoding accuracy and performance.

Limitations of OSM

  • Geocoding and reverse geocoding may be less accurate than Google Maps in some regions.
  • Tile loading speed depends on the OSM tile server and may vary by region.
  • Advanced features like Directions API and Distance Matrix are not natively supported.

Best Practices & Tips

Follow these guidelines to get the most out of your zone configuration.

Start with Your Primary City
Begin by creating a zone for your main city or launch area. Get pricing, vehicle types, and operations running smoothly before expanding to additional zones.

Zone Design Tips

  • Use enough vertices — Place at least 8-12 points when drawing the boundary to create a smooth, accurate polygon that matches the real-world service area.
  • Avoid self-intersecting polygons — Ensure boundary lines do not cross each other, as this can cause fare calculation errors.
  • Consider adjacent zones — If you plan to expand, design the initial zone boundary with room for neighboring zones. Overlapping zones can cause confusing behavior.
  • Account for landmarks — Include key pickup/dropoff points like airports, train stations, shopping centers, and business districts within the zone boundary.

Operational Considerations

  • Zone naming convention — Use clear, consistent names. Include city and region (e.g., "Paris - Central", "Paris - suburbs") for multi-zone cities.
  • Currency consistency — Ensure the zone currency matches the local currency to avoid fare confusion.
  • Payment methods — Enable all payment methods relevant to your operating region. Cash is essential in many markets.
  • Testing — Before activating a zone, test the boundary by requesting rides from points inside, outside, and near the boundary edge.
