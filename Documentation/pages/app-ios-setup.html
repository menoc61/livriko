iOS Setup Detail

This guide covers the detailed iOS-specific configuration for both the User and Driver apps, including provisioning profiles, certificates, entitlements, permissions, and APNs setup.

Prerequisites

  • Mac computer (Intel or Apple Silicon) with macOS Ventura or later
  • Xcode 15+ installed from the Mac App Store
  • CocoaPods installed (sudo gem install cocoapods)
  • Apple Developer Program membership ($99/year) for production builds
  • React Native environment set up (see prerequisites)

Apple Developer Program Required

You must be enrolled in the Apple Developer Program to create provisioning profiles, push notification certificates, and submit to the App Store. Free accounts are limited to simulators and device debugging only.

Step 1: Install CocoaPods

CocoaPods manages native iOS dependencies for React Native. Install it globally on your Mac:

# Install CocoaPods
sudo gem install cocoapods

# Verify installation
pod --version
# Should output: 1.15.x or similar

Step 2: Install Pods

Navigate to the iOS directory of each app and install the CocoaPods dependencies:

User App:

cd Taxido_user/ios
pod install

Driver App:

cd Taxido_driver/ios
pod install

Open the .xcworkspace File

Always open the .xcworkspace file (not the .xcodeproj file) in Xcode after running pod install. Opening the wrong file will cause build errors because CocoaPods-managed dependencies will not be linked.

Step 3: Provisioning Profiles & Certificates

iOS requires code signing certificates and provisioning profiles for both development and distribution. Manage these at the Apple Developer Portal.

Certificate Types

Certificate Purpose Required For
Apple Distribution Sign the app for App Store or Ad Hoc distribution App Store submission, TestFlight
Apple Development Sign the app for development and testing on devices Local testing on physical devices

Provisioning Profile Types

Profile Purpose Restriction
App Store Submit to the App Store Can only be used for App Store builds
Ad Hoc Distribute to specific registered devices Limited to listed device UDIDs
Development Debug on development devices Limited to development team devices

Configure Signing in Xcode

Open .xcworkspace

Open LivrikoUser.xcworkspace (or LivrikoDriver.xcworkspace) in Xcode.

Select Project

Click the project in the navigator, then select the target under Targets.

Signing & Capabilities

Go to the Signing & Capabilities tab. Select your Team (Apple Developer account).

Set Bundle Identifier

Set the Bundle Identifier (e.g., com.yourcompany.livriko.user). Ensure it matches your App ID in the Developer Portal.

Automatic Signing

Ensure Automatically manage signing is checked for development. For distribution builds, you may need manual signing with explicit provisioning profiles.

Step 4: Entitlements

Entitlements are capabilities your app requests from iOS. They are configured in Xcode's Signing & Capabilities tab.

User App Entitlements

Entitlement Purpose Required
Push Notifications Receive ride updates and alerts via APNs Yes
Associated Domains Universal Links and Apple Sign-In If using Apple Sign-In

Driver App Entitlements

Entitlement Purpose Required
Push Notifications Receive ride request notifications via APNs Yes
Background Modes → Location Continuous location tracking while app is backgrounded Yes
Associated Domains Universal Links and Apple Sign-In If using Apple Sign-In

To add a capability: click + Capability in the Signing & Capabilities tab, then select the capability from the list.

Step 5: Info.plist Permissions

The Info.plist file must contain usage description strings for every permission the app requests. Missing descriptions will cause the app to crash or be rejected by App Store review.

<!-- Info.plist -->
<key>NSLocationWhenInUseUsageDescription</key>
<string>Livriko needs your location to find nearby drivers and calculate your route.</string>

<key>NSLocationAlwaysAndWhenInUseUsageDescription</key>
<string>Livriko tracks your location in the background to provide real-time ride updates and driver matching.</string>

<key>NSCameraUsageDescription</key>
<string>Livriko uses the camera to scan documents and take profile photos.</string>

<key>NSPhotoLibraryUsageDescription</key>
<string>Livriko accesses your photo library to upload profile pictures and ride receipts.</string>

<key>NSMicrophoneUsageDescription</key>
<string>Livriko uses the microphone for in-app voice calls with drivers.</string>

<key>NSFaceIDUsageDescription</key>
<string>Livriko uses Face ID for secure app authentication.</string>

Missing Descriptions = Crash & Rejection

If any permission usage description is missing from Info.plist, the app will crash when requesting that permission. App Store review will also reject the app for missing descriptions. Always include all required strings.

Step 6: APNs (Apple Push Notification Service)

Push notifications require an APNs key or certificate configured in both Apple Developer Portal and Firebase.

Create APNs Key

In the Apple Developer Portal, go to Keys and click +. Enable Apple Push Notifications service and download the .p8 key file.

Add to Firebase

In the Firebase Console, go to Project Settings → Cloud Messaging → Apple app configuration. Upload the APNs authentication key (.p8 file) and enter your Key ID and Team ID.

Register for Notifications

In the app code, request notification permission and register the device token with Firebase. The token is automatically used by @react-native-firebase/messaging.

Step 7: Google Services Configuration

Add the Google Services plist file for Firebase and Maps integration:

  1. Download GoogleService-Info.plist from the Firebase console
  2. Drag the file into the Xcode project navigator
  3. Ensure "Copy items if needed" is checked
  4. Ensure the file is added to the correct target (User or Driver)
  5. Add the Google Maps SDK initialization code in AppDelegate.m or AppDelegate.swift

Step 8: Run on Simulator

Test the apps on the iOS Simulator:

# User App
cd Taxido_user
npx react-native run-ios

# Driver App
cd Taxido_driver
npx react-native run-ios

Step 9: Run on Physical Device

Connect Device

Connect the iPhone to your Mac via USB cable.

Enable Developer Mode

On the iPhone, go to Settings → Privacy & Security → Developer Mode and toggle it on.

Select Device in Xcode

In Xcode, select the connected device from the scheme dropdown in the toolbar.

Build and Run

Click the Run button (or press Cmd+R) to build and install the app on the device.

Driver App Background Location

The Driver app requires background location access for real-time tracking. In Xcode, go to Signing & Capabilities → + Capability → Background Modes and enable Location updates. Also add the UIBackgroundModes key with location value to Info.plist.
