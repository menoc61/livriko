Wallet

Manage digital wallets for riders, drivers, and fleet managers — handle credits, debits, refunds, and transaction history from a single interface.

Overview

The Wallet system is the financial backbone of the Livriko platform. It enables seamless cashless transactions between riders and drivers, supports admin-initiated adjustments, and provides a transparent record of every financial movement on your platform.

Livriko maintains three distinct wallet types, each serving a specific purpose in the ecosystem.

Rider Wallet

Riders top up their wallet to pay for rides. Supports multiple payment methods including credit cards and mobile money. Balance is deducted automatically when a ride is completed.

Driver Wallet

Drivers receive earnings after platform commission is deducted. Earnings accumulate with each completed ride and can be withdrawn to a linked bank account.

Fleet Wallet

Fleet managers have a consolidated wallet that aggregates earnings from all vehicles in their fleet. Useful for businesses managing multiple drivers and vehicles.

Managing Transactions

As an admin, you can manually credit or debit any wallet on the platform. This is essential for handling refunds, bonuses, promotional credits, and corrections.

1

Select Wallet Type

Go to Livriko Management → Wallet. Choose whether you are managing a Rider, Driver, or Fleet wallet by selecting the appropriate tab.

2

Find the Account

Search for the specific rider, driver, or fleet manager by name, email, or phone number. Click on the account to view their current balance and transaction history.

3

Enter Amount and Select Action

Enter the transaction amount, then select either Credit (add funds) or Debit (deduct funds). Always add a descriptive reason note — this appears in the transaction history for both you and the account holder.

4

Confirm the Transaction

Review the details carefully before confirming. The transaction is processed immediately and the wallet balance updates in real-time. The account holder will see the new balance and transaction in their app.

Double-Check Before Confirming

Wallet transactions are processed immediately and cannot be automatically reversed. Always verify the account, amount, and action (credit/debit) before confirming. If you make an error, you will need to create a reverse transaction manually.

Credit Flow — Adding Funds

Crediting a wallet adds funds to the account. Common use cases for manual credits include:

  • Refunds — Return funds to a rider after a disputed ride, cancellation, or platform error.
  • Bonuses — Reward drivers with performance bonuses, sign-up incentives, or referral rewards.
  • Promotions — Credit promotional funds to rider wallets as part of marketing campaigns.
  • Compensation — Compensate a rider or driver for a poor experience, service disruption, or delay.

When you credit a wallet, the following happens:

  1. The wallet balance increases by the specified amount.
  2. A transaction record is created with the type "Credit", the amount, reason note, and admin ID.
  3. The account holder receives a notification (if enabled) confirming the credit.
  4. The transaction appears in their wallet history in the app.

Debit Flow — Deducting Funds

Debiting a wallet removes funds from the account. Use this cautiously and only for valid reasons. Common use cases include:

  • Correction — Reverse an erroneous credit or fix a system glitch that incorrectly added funds.
  • Penalty — Deduct a penalty for policy violations (e.g., driver cancellation fees, rider no-show charges).
  • Subscription Fees — Manually deduct a Plan subscription fee if not handled automatically.
Sufficient Balance Check

The system prevents debiting more than the available balance. If you attempt to debit an amount that exceeds the wallet balance, the transaction will fail. For large deductions, verify the current balance first to avoid confusion.

Transaction History

Every wallet transaction is logged with full details and is accessible from both the admin panel and the user's app. The transaction history provides complete financial transparency.

Field Description
Date & Time When the transaction was processed (timestamp in the platform's configured timezone).
Type Credit (incoming funds) or Debit (outgoing funds). Also includes system-generated entries like ride payments and commission deductions.
Amount The exact amount involved in the transaction, displayed in the platform's configured currency.
Balance After The wallet balance immediately after this transaction was processed. Useful for reconciling account statements.
Reason / Description A human-readable note explaining why the transaction occurred (e.g., "Refund for cancelled ride #1234", "Performance bonus — March 2025").
Reference Optional reference ID linking the transaction to a ride, order, or admin action for audit purposes.
Filtering Transactions

Use the date range filter and transaction type filter on the history page to quickly locate specific entries. You can also export transaction data to CSV for accounting and reconciliation purposes.

Wallet Balance in Apps

Both riders and drivers can view their wallet balance directly in their respective apps:

  • Rider App — The wallet balance is displayed in the profile section. Riders can top up using configured payment methods and see their full transaction history.
  • Driver App — Drivers see their current earnings balance and can request a withdrawal. The withdrawal is processed to their linked bank account.
  • Fleet Manager Dashboard — Fleet managers see a consolidated balance for their entire fleet, with per-vehicle and per-driver breakdowns.
Real-Time Updates

Wallet balances update in real-time across all platforms. When an admin credits or debits a wallet, the change is immediately reflected in the user's app without requiring a page refresh or app restart.
