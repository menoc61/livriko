iOS Build

This guide covers building and releasing the Livriko iOS apps to the Apple App Store. This process requires an Apple Developer account, Xcode, and properly configured certificates and provisioning profiles.

Archive Steps

The archive process packages your app into a distributable format for TestFlight or the App Store. Follow these steps in Xcode:

Open .xcworkspace

Open LivrikoUser.xcworkspace (or LivrikoDriver.xcworkspace) in Xcode.

Select Device Target

Select Any iOS Device (arm64) from the scheme dropdown in the Xcode toolbar. Do not select a simulator.

Start Archive

Go to Product → Archive. Wait for the archive to complete (this may take several minutes depending on project size).

Open Archives Window

When the archive completes, the Archives window opens automatically. If not, go to Window → Organizer → Archives.

Distribute App

Select the archive and click Distribute App. Choose App Store Connect → Upload. Follow the prompts to complete the upload.

Certificates & Provisioning

iOS requires code signing certificates and provisioning profiles. Manage these at the Apple Developer Portal.

Certificate Type Purpose Required For
Apple Distribution Sign the app for App Store distribution App Store submission
Apple Development Sign the app for development/testing Local testing on devices
Provisioning Profile (App Store) Links distribution certificate to App ID App Store and TestFlight uploads
Provisioning Profile (Development) Links development certificate to App ID and devices Debug builds on physical devices

Automatic vs Manual Signing

For development, use Xcode's automatic signing. For distribution builds (App Store), you may need to create explicit provisioning profiles manually in the Developer Portal and download them to Xcode.

TestFlight

TestFlight is Apple's platform for beta testing iOS apps. Use it to distribute pre-release builds to internal and external testers before the official App Store release.

Internal Testing

  1. Upload the archive to App Store Connect (as described in the archive steps)
  2. In App Store Connect, go to TestFlight
  3. Select the build and add internal testers (up to 100, must be on your App Store Connect team)
  4. Internal testers receive an email with instructions to install via the TestFlight app
  5. No beta review required for internal testing

External Testing

  1. In App Store Connect → TestFlight, select the build
  2. Click External Testing → Create New Group
  3. Add external testers by email (up to 10,000 per app)
  4. Submit for Beta App Review — Apple reviews external test builds
  5. Review typically takes 24-48 hours
  6. Once approved, testers receive an email to install via TestFlight

TestFlight Limits

TestFlight allows up to 10,000 external testers per app. External testers require Apple's beta app review, which typically takes 24-48 hours. Internal testers (up to 100) can install immediately without review.

App Store Connect

Before submitting to the App Store, you must prepare your app listing in App Store Connect.

Required Metadata

Field Description Requirements
App Name The name displayed on the App Store Max 30 characters
Subtitle Brief description shown below the app name Max 30 characters
Description Detailed app description Max 4000 characters
Keywords Search keywords for App Store discovery Max 100 characters, comma-separated
App Icon 1024x1024 PNG, no transparency or rounded corners Required
Screenshots App screenshots for all required device sizes Required for all supported devices
Privacy Policy URL Link to your privacy policy Required
Support URL Link to your support page Required
Category App Store category (e.g., Transportation) Required (primary + optional secondary)
Age Rating Age rating questionnaire responses Required
Pricing App price tier (free or paid) Required

Screenshot Requirements

Apple requires screenshots for specific device sizes. Use the following sizes for Livriko apps:

  • iPhone 6.9" (iPhone 16 Pro Max): 1320 × 2868 pixels
  • iPhone 6.7" (iPhone 15 Plus): 1290 × 2796 pixels
  • iPhone 6.5" (iPhone 11 Pro Max): 1242 × 2688 pixels
  • iPhone 5.5" (iPhone 8 Plus): 1242 × 2208 pixels
  • iPad 12.9" (iPad Pro 6th gen): 2048 × 2732 pixels

Screenshot Tips

Take screenshots from the actual app, not from marketing mockups. Show key features: home screen, ride booking, tracking, payment, and profile. Use real data (not lorem ipsum) for a professional appearance.

Pricing & Availability

Set your app pricing and availability in App Store Connect:

  • Free or Paid: Livriko apps are typically free; revenue comes from ride commissions
  • Availability: Select the countries/regions where the app should be available
  • Release: Choose manual release (submit when ready) or automatic release (publish immediately after approval)

Common App Store Rejections

Avoid these common reasons for App Store rejection:

Rejection Reason How to Avoid
Missing privacy descriptions Ensure all NS*UsageDescription keys are in Info.plist
Broken functionality Test all features thoroughly before submission. Test on real devices, not just simulators.
Incomplete metadata Fill in all required fields: description, screenshots, keywords, privacy policy URL
Placeholder content Remove all placeholder text, lorem ipsum, and test data from the app
Crash on launch Test the app on multiple device sizes and iOS versions before submission
Missing Sign in with Apple If offering social login, you must also offer Sign in with Apple (Apple requirement)

Info.plist Privacy Descriptions

Ensure your Info.plist contains all required privacy usage descriptions (NSLocationWhenInUseUsageDescription, NSLocationAlwaysAndWhenInUseUsageDescription, etc.). Missing descriptions will cause the app to crash on iOS and will be rejected by App Store review. See iOS Setup Detail for the complete list.

Post-Submission

After submitting your app to the App Store:

  1. App Review: Apple's review team typically reviews apps within 24-48 hours
  2. Status Updates: Monitor the status in App Store Connect → App Store → App Review
  3. Rejection Handling: If rejected, read the rejection notes carefully, fix the issues, and resubmit
  4. Release: Once approved, release the app manually or wait for automatic release
  5. Monitor: Check crash reports and user reviews in App Store Connect after launch
