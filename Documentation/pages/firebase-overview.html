Firebase Overview

Firebase is the backbone of Livriko's real-time communication and authentication layer. It powers push notifications, user authentication, cloud functions, and real-time data synchronization between the admin panel and mobile apps.

What Firebase Provides for Livriko

Livriko integrates the following Firebase services to deliver a complete mobility experience:

Service Purpose in Livriko
Firebase Authentication User sign-up and sign-in via email/password, Google, Facebook, and Apple. Handles session management and identity verification.
Firebase Cloud Messaging (FCM) Push notifications for ride updates, promotions, alerts, driver assignments, and payment confirmations.
Cloud Firestore Real-time NoSQL database for driver locations, ride data, messaging, and session tracking.
Cloud Functions Serverless backend logic for order tracking, notification triggers, payment webhooks, and data cleanup.
Firebase Hosting Fast, secure hosting for the Livriko landing page and static assets with global CDN.

Setup Checklist

Complete the following steps to fully configure Firebase for Livriko:

Step Status Description
1 Create a Firebase project at console.firebase.google.com
2 Add Android app (User) with package name com.livriko.user and download google-services.json
3 Add iOS app (User) with bundle ID and download GoogleService-Info.plist
4 Repeat steps 2–3 for the Driver app (com.livriko.driver)
5 Generate SHA-1 and SHA-256 keys and add them to Firebase
6 Connect the Laravel admin panel via Service Account credentials
7 Configure Firebase Cloud Messaging server key in admin settings
8 Enable Social Login providers (Google, Apple) and configure billing if required
9 Deploy Firestore security rules and Cloud Functions

How Firebase Connects to Livriko

Firebase acts as the real-time bridge between three components of the Livriko platform:

Admin Panel → Firebase

The Laravel admin panel connects to Firebase using the Firebase Admin SDK (via Service Account credentials). This allows the admin to send push notifications, manage user accounts, and query Firestore data directly from the server.

Mobile Apps → Firebase

Both the User and Driver apps use the Firebase Client SDK to authenticate users, receive push notifications, store ride data in Firestore, and listen for real-time location updates.

Firebase → Cloud Functions

Cloud Functions respond to Firestore document changes and authentication events, automatically triggering notifications, updating ride statuses, and cleaning up expired data.

Firebase Project Structure

When you create your Firebase project, it will contain the following key components:

your-firebase-project/
├── Authentication/
│   ├── Sign-in methods (Email/Password, Google, Apple)
│   └── Users list
├── Firestore Database/
│   ├── riders/
│   ├── drivers/
│   ├── rides/
│   ├── locations/
│   ├── messages/
│   └── notifications/
├── Cloud Functions/
│   └── functions/ (Node.js source)
├── Hosting/
│   └── public/ (static files)
└── Project Settings/
    ├── General (project ID, API keys)
    ├── Service Accounts (credentials for Laravel)
    └── Cloud Messaging (server key, sender ID)

Prerequisites

Before starting the Firebase setup, ensure you have:

  • Google Account — Required to access the Firebase Console
  • Laravel Backend — The Livriko admin panel must be installed and running
  • Mobile App Source Code — Access to the User and Driver app projects
  • Node.js (v18+) — Required for Cloud Functions deployment
  • Firebase CLI — Will be installed during Cloud Functions setup
Warning

Social Login (Google Sign-In and Apple Sign-In) requires the Firebase Blaze (pay-as-you-go) plan. Make sure billing is enabled before attempting to configure social authentication. See the Billing page for details.
