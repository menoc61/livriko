Create User App

Set up and configure the Livriko User mobile application. This guide covers the initial project configuration, API connection, Firebase setup, and running the app on a simulator or device.

User App Directory

The User App is located in the Taxido_user/ directory of the Livriko repository. This is a standalone React Native project that can be built and run independently from the Driver App:

livriko/
├── Taxido_user/          # User App (passenger-facing)
│   ├── android/          # Android native project
│   ├── ios/              # iOS native project
│   ├── src/              # React Native source code
│   │   ├── config/       # API and app configuration
│   │   ├── context/      # React context providers
│   │   ├── screens/      # Screen components
│   │   ├── components/   # Reusable UI components
│   │   ├── assets/       # Images, fonts, animations
│   │   └── themes/       # Color themes and styles
│   ├── app.json          # App metadata
│   ├── package.json      # Dependencies
│   └── tsconfig.json     # TypeScript configuration
└── Taxido_driver/        # Driver App

Step 1: Install Dependencies

Navigate to the User App directory and install all required packages:

cd Taxido_user
npm install

This installs all React Native dependencies including navigation, maps, state management, and UI components. The process may take a few minutes.

Tip

If you encounter dependency resolution errors, try npm install --force or delete node_modules and package-lock.json before retrying.

Step 2: Configure API URL

Set the backend API endpoint that the app will communicate with:

File: Taxido_user/src/config/config.tsx

// Taxido_user/src/config/config.tsx
export const URL = 'https://your-backend-url.com';

For local development, use your machine's local IP address (not localhost) so the emulator can reach the backend:

// Local development example
export const URL = 'http://192.168.1.100/livriko/public';
Warning

Do not use http://localhost when running on a physical device or Android emulator. The emulator uses a different network context. Use your machine's actual IP address instead.

Step 3: Configure Firebase

The User App uses Firebase for push notifications, authentication, and analytics. You need to configure the Firebase project for both platforms:

Android — google-services.json

Download google-services.json from the Firebase Console and place it in:

Taxido_user/android/app/google-services.json

iOS — GoogleService-Info.plist

Download GoogleService-Info.plist from the Firebase Console and place it in:

Taxido_user/ios/GoogleService-Info.plist
Important

Ensure the Firebase project's bundle identifier matches the one configured in your iOS and Android projects (e.g., com.livriko.user). A mismatch will cause authentication and push notification failures.

Step 4: Configure Google Maps Key

Set your Google Maps API key for map rendering and geocoding:

File: Taxido_user/src/context/index.tsx

// Taxido_user/src/context/index.tsx
export const GOOGLE_MAPS_API_KEY = 'YOUR_GOOGLE_MAPS_API_KEY';

You also need to configure the key in the native projects:

Android

Add the key to Taxido_user/android/app/src/main/AndroidManifest.xml:

<meta-data
  android:name="com.google.android.geo.API_KEY"
  android:value="YOUR_GOOGLE_MAPS_API_KEY"/>

iOS

Add the key to Taxido_user/ios/Taxido_user/AppDelegate.mm or via Info.plist depending on your setup.

Step 5: Run on Emulator

With all configuration complete, run the app on your target platform:

Android

cd Taxido_user
npm run android

iOS

cd Taxido_user/ios
pod install
cd ..
npm run ios
Tip

The first build may take several minutes as React Native compiles native code. Subsequent builds will be faster due to caching.

Splash Screen

Replace the default splash screen image with your custom branding:

File: Taxido_user/src/assets/images/splash.png

The splash screen image should be at least 1080 x 1920 px for high-resolution displays. Use a PNG file with a transparent or solid background. Ensure the image is centered and looks good on both small phones and large tablets.

App Metadata

Update the app metadata in app.json to reflect your branding. This file controls the app name as React Native sees it and is used during the build process:

{
  "name": "YourAppName",
  "displayName": "Your App Name",
  "expo": {
    "name": "YourAppName",
    "slug": "your-app-name",
    "version": "1.0.0"
  }
}
Warning

The name field in app.json must not contain spaces. Use camelCase or PascalCase instead. The displayName field can contain spaces and is shown to the user.

Splash Screen Configuration

The splash screen is configured in the React Native project. Check the splash screen library configuration for customization options such as background color, resize mode, and duration:

  • Background color — Match your primary brand color
  • Resize mode — cover fills the screen, contain keeps the image visible
  • Duration — How long the splash screen displays before transitioning to the app
Tip

After configuring the User App, run it on an emulator to verify all changes are applied correctly before moving on to the Driver App.

Testing the User App

Once configuration is complete, verify the following features work correctly on a running emulator or device:

  • Login/Registration — Test email, phone, Google, and Apple sign-in flows
  • Map loading — Verify Google Maps renders correctly with your API key
  • API connection — Check that vehicle types and pricing load from the backend
  • Push notifications — Test receiving notifications via Firebase Cloud Messaging
  • Ride booking — Complete a test ride flow from pickup to dropoff
  • Payments — Verify payment methods work correctly for your configured gateways
  • Location services — Confirm the app requests and receives location permissions
  • Error handling — Test with no internet connection to verify offline behavior
