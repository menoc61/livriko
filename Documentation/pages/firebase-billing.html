Firebase Billing

Understanding when you need to enable billing on your Firebase project, what the free tier includes, and how to optimize costs.

Why Billing Is Required

The Firebase Spark (free) plan does not support certain features required by Livriko, most notably Social Login (Google Sign-In and Apple Sign-In). To enable these features, you must upgrade to the Blaze (pay-as-you-go) plan.

No Immediate Charges

Enabling the Blaze plan does not mean you will be charged immediately. Google provides generous free tier quotas that are sufficient for most deployments. You only pay for usage beyond the free tier.

Enable Billing

Open Project Settings

Go to Firebase Console → Project Settings → Usage and billing.

View Current Plan

Click "Details & usage" to see your current plan and usage.

Modify Plan

Click "Modify plan" and select "Blaze - Pay as you go".

Link Billing Account

Follow the prompts to link a Google Cloud billing account. Confirm the upgrade.

Free Tier Quotas (Blaze Plan)

The Blaze plan includes the following free monthly quotas. You will only be charged if you exceed these limits:

Service Free Tier Limit Overage Cost
Authentication 50,000 monthly active users $0.01 per additional user
Cloud Firestore 50K reads / 20K writes per day $0.06 per 100K reads, $0.18 per 100K writes
Cloud Functions 2M invocations per month $0.40 per million invocations
Cloud Messaging Unlimited Free for all usage
Cloud Storage 5 GB stored $0.026 per GB per month
Hosting 10 GB stored $0.026 per GB per month
Good News

For most Livriko deployments, the free tier is more than sufficient. You will typically only exceed limits if you have a very large number of active users (10K+) or heavy Firestore usage.

Monitoring Usage

Monitor your Firebase usage to avoid unexpected charges:

Open Usage Dashboard

Go to Firebase Console → Usage and billing → Details & usage.

Review Metrics

Check the usage graphs for each service. Pay attention to trends and approaching limits.

Setting Budget Alerts

Set up budget alerts in Google Cloud Console to get notified before exceeding your budget:

Open Google Cloud Console

Go to console.cloud.google.com/billing.

Select Your Budget

Click on your budget and set alert thresholds (e.g., 50%, 90%, 100%).

Configure Notifications

Add email addresses to receive budget alerts. Consider setting up SMS alerts for critical thresholds.

Cost Optimization Tips

  • Optimize Firestore reads — Use queries efficiently and avoid fetching unnecessary data
  • Limit Cloud Functions invocations — Avoid unnecessary function calls and batch operations
  • Use FCM topics — Send bulk notifications via topics instead of individual device tokens
  • Clean up old data — Remove expired Firestore documents and old notifications regularly
  • Monitor usage patterns — Set up alerts to catch usage spikes early

Common Cost Surprises

Scenario Impact Prevention
High Firestore reads Real-time listeners generating excessive reads Optimize query patterns, limit listener scope
Cloud Functions cold starts Frequent invocations increasing costs Batch operations, reduce function calls
Storage growth Old files accumulating in Cloud Storage Implement lifecycle policies, clean up old files
Unexpected traffic spikes Sudden increase in API calls Set budget alerts, monitor usage dashboards
