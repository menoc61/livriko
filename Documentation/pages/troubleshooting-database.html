Database Upgrade

This guide covers running database migrations, creating backups, and rolling back changes in your Livriko deployment.

Before You Upgrade

Critical

Always create a full backup of your database before running migrations, especially in production environments. Migration failures can result in data loss. Test migrations on a staging environment first whenever possible.

Step 1: Backup Database

Before running any migrations, create a backup of your database:

Using mysqldump

# Create a timestamped backup
mysqldump -u root -p livriko > backup_$(date +%Y%m%d_%H%M%S).sql

# Example output: backup_20240620_143000.sql

Using Laravel Backup

If you have the spatie/laravel-backup package installed:

# Create a full application backup
php artisan backup:run

# Create only a database backup
php artisan backup:run --only-db

# List all backups
php artisan backup:list

Restore from Backup

# Restore from a mysqldump backup
mysql -u root -p livriko < backup_20240620_143000.sql

# Or using Laravel
php artisan backup:restore

Step 2: Run Migrations

After backing up, run the database migrations:

# Run all pending migrations
php artisan migrate

# Run without confirmation prompt (useful for automation)
php artisan migrate --force
What Migrations Do

Migration files in database/migrations contain SQL statements that create or modify database tables. Running php artisan migrate executes all pending migrations in order.

Step 3: If Errors Occur

If the migration fails, use rollback commands to undo changes:

# Rollback the last migration batch
php artisan migrate:rollback

# Rollback the last 3 batches
php artisan migrate:rollback --step=3

# Rollback all migrations
php artisan migrate:reset

# Rollback all, then re-run all migrations
php artisan migrate:refresh

# Rollback all, re-run, and seed
php artisan migrate:refresh --seed

Step 4: Seed Database

After migrations, seed the database with default data if needed:

# Run all seeders
php artisan db:seed

# Run a specific seeder
php artisan db:seed --class=VehicleTypeSeeder

# Refresh migrations and seed
php artisan migrate:refresh --seed

Common Migration Issues

Issue Cause Solution
Column already exists Migration was partially applied or re-run php artisan migrate:rollback then php artisan migrate
Table does not exist Migration depends on a table from a previous migration Run php artisan migrate:fresh --seed to start fresh
Duplicate entry error Seeder trying to insert existing data Use firstOrCreate or check for duplicates before inserting
Foreign key constraint fails Referenced table doesn't exist or has different data Ensure migrations run in the correct order
Unknown column Code references a column that doesn't exist yet Run migrations before accessing the new column

Rollback Strategy

A proper rollback strategy ensures you can recover from failed upgrades:

Before Upgrade

Create a full database backup. Note the current Livriko version and migration batch number.

During Upgrade

Run migrations one batch at a time. Test each batch before proceeding.

After Upgrade

Verify the application works correctly. Check all major features.

Rollback (If Needed)

Restore from backup if the upgrade fails. Use php artisan migrate:rollback for minor issues.

Step-by-Step Upgrade Procedure

# 1. Create backup
mysqldump -u root -p livriko > pre_upgrade_backup.sql

# 2. Enable maintenance mode
php artisan down

# 3. Pull latest code
git pull origin main

# 4. Install dependencies
composer install --no-dev --optimize-autoloader

# 5. Run migrations
php artisan migrate --force

# 6. Clear caches
php artisan config:clear
php artisan cache:clear
php artisan route:clear

# 7. Seed if needed
php artisan db:seed --force

# 8. Disable maintenance mode
php artisan up

# 9. Verify application
curl -I https://your-domain.com
Important

Always test your upgrade process on a staging environment before applying it to production. This helps identify potential issues without affecting your users.
