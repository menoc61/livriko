Key Folders Explained

src/screens/

Each screen is a top-level view in the app. Screens are organized by feature domain (auth, home, ride, profile, payment/earnings). Each screen file contains a React component that renders a full page and handles its own navigation events and lifecycle hooks.

src/components/

Reusable UI components that are shared across multiple screens. Components are organized into subdirectories by domain: common for generic elements like buttons and modals, map for map-related rendering, and ride for ride-specific cards and modals. Components receive props and manage minimal local state.

src/services/

API service modules that handle all HTTP communication with the Livriko backend. Each service file groups related endpoints: authService.js for login and registration, rideService.js for ride lifecycle operations, and so on. The api.js file configures a shared Axios instance with base URL, interceptors, and auth token injection.

src/store/

Redux Toolkit state management. The index.js file creates and configures the Redux store. Slice files define reducers and async thunks for specific domains: authentication state, ride state, user/driver profile state, and location tracking state.

src/utils/

Shared utility functions used throughout the app. constants.js defines app-wide constants (API endpoints, timeout values), helpers.js contains formatting and calculation functions, and storage.js wraps AsyncStorage for persistent key-value storage.

src/assets/

Static assets bundled with the app, including image files (logos, placeholders, onboarding illustrations) and custom fonts. Assets are referenced via relative imports in components and styles.

Shared Configuration

Both apps share the same configuration file structure (config.js) and API service pattern. When updating the API URL, Firebase configuration, or Google Maps key, you must update it in both Taxido_user/src/config/config.js and Taxido_driver/src/config/config.js.

Configuration Files

Several root-level configuration files control how the React Native project builds and runs:

File Purpose
package.json Node.js dependencies and npm scripts for building, running, and testing
app.json React Native app metadata — name, slug, version, platform-specific config
babel.config.js Babel transpiler presets and plugins for JSX and modern JavaScript
metro.config.js Metro bundler configuration — file resolution, transforms, and optimization
.env Local environment variables (API URL, map keys). Never commit to version control.
.env.example Template for .env with placeholder values. Safe to commit.

Don't Modify Native Code Directly

Avoid editing files inside the android/ or ios/ directories unless absolutely necessary. Changes to native code can be overwritten during upgrades. Use React Native libraries and native modules via npm packages instead.

Best Practice

Keep the src/ directory clean and well-organized. When adding a new feature, place screens in the appropriate screens/ subdirectory, extract reusable UI into components/, and create a new service file in services/ if the feature requires API calls.
