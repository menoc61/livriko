Create Driver App

Set up and configure the Livriko Driver mobile application. The Driver App has some important differences from the User App, including background location tracking, navigation integration, and earnings management.

Driver App Directory

The Driver App is located in the Taxido_driver/ directory of the Livriko repository. It is a standalone React Native project with its own dependencies and configuration:

livriko/
├── Taxido_user/          # User App (passenger-facing)
└── Taxido_driver/        # Driver App (driver-facing)
    ├── android/          # Android native project
    ├── ios/              # iOS native project
    ├── src/              # React Native source code
    │   ├── config/       # API and app configuration
    │   ├── context/      # React context providers
    │   ├── screens/      # Screen components
    │   ├── components/   # Reusable UI components
    │   ├── assets/       # Images, fonts, animations
    │   └── theme/        # Color themes and styles (singular)
    ├── app.json          # App metadata
    ├── package.json      # Dependencies
    └── tsconfig.json     # TypeScript configuration

Key Differences from User App

The Driver App includes several features not present in the User App:

Feature Driver App User App
Background Location Required for ride matching while app is in background Not required
Turn-by-Turn Navigation Integrated Google Maps navigation for route planning Basic map view only
Earnings Dashboard Daily, weekly, and monthly earnings tracking Not applicable
Online / Offline Toggle Driver controls availability status Not applicable
Document Management Upload and manage license, insurance, registration Not applicable
ProGuard Minification Enabled in release builds for smaller APK Disabled by default

Step 1: Install Dependencies

Navigate to the Driver App directory and install all required packages:

cd Taxido_driver
npm install
Tip

The Driver App has a slightly different dependency set than the User App, including additional packages for background location tracking and navigation. Do not share node_modules between the two projects.

Step 2: Configure API URL

Set the same backend API endpoint used by the User App. Both apps must connect to the same backend to share ride data and user information:

File: Taxido_driver/src/config/config.tsx

// Taxido_driver/src/config/config.tsx
export const URL = 'https://your-backend-url.com';
Note

For local development, use your machine's actual IP address (e.g., http://192.168.1.100/livriko/public) instead of localhost, as emulators and devices cannot reach localhost.

Step 3: Configure Firebase

The Driver App uses Firebase for push notifications and location services. Use the same Firebase project as the User App, but with a separate app registration:

Android — google-services.json

Taxido_driver/android/app/google-services.json

iOS — GoogleService-Info.plist

Taxido_driver/ios/GoogleService-Info.plist
Warning

The Driver App must use a different bundle identifier than the User App (e.g., com.livriko.driver instead of com.livriko.user). Register a separate app in the Firebase Console for the Driver App.

Step 4: Configure Google Maps Key

Set your Google Maps API key for map rendering and navigation:

File: Taxido_driver/src/context/index.tsx

// Taxido_driver/src/context/index.tsx
export const GOOGLE_MAPS_API_KEY = 'YOUR_GOOGLE_MAPS_API_KEY';

Step 5: Background Location Permissions

The Driver App requires background location access for continuous driver tracking. Ensure the following permissions are configured:

Android — AndroidManifest.xml

<uses-permission android:name="android.permission.ACCESS_BACKGROUND_LOCATION"/>
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION"/>
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION"/>

iOS — Info.plist

<key>UIBackgroundModes</key>
<array>
    <string>location</string>
</array>

<key>NSLocationAlwaysAndWhenInUseUsageDescription</key>
<string>Livriko needs your location to match you with nearby rides.</string>

Step 6: Android Build Configuration

The Driver App enables ProGuard minification and resource shrinking in release builds to reduce APK size and improve performance:

File: Taxido_driver/android/app/build.gradle

android {
    namespace "com.livriko.driver"
    defaultConfig {
        applicationId "com.livriko.driver"
        versionCode 1
        versionName "3.0.0"
    }
    buildTypes {
        release {
            minifyEnabled true
            shrinkResources true
            proguardFiles getDefaultProguardFile(
              "proguard-android-optimize.txt"
            ), "proguard-rules.pro"
        }
    }
}

Step 7: Run on Emulator

With all configuration complete, run the Driver App:

Android

cd Taxido_driver
npm run android

iOS

cd Taxido_driver/ios
pod install
cd ..
npm run ios
Tip

To test the full ride flow, run both the User App and Driver App on separate emulators or devices connected to the same backend.

Splash Screen

Replace the default splash screen image with your custom Driver App branding:

File: Taxido_driver/src/assets/images/splash.png

The splash screen should match the Driver App's branding and be distinct from the User App to help drivers quickly identify the correct app on their device.

Testing the Driver App

Once configuration is complete, verify the following features work correctly on a running emulator or device:

  • Driver login — Test driver authentication and profile loading
  • Online/Offline toggle — Verify the driver can go online and appear on the map
  • Background location — Confirm location is shared while the app is in the background
  • Ride requests — Test receiving and responding to ride requests from the User App
  • Navigation — Verify Google Maps navigation launches correctly
  • Earnings — Check that the earnings dashboard displays trip data
  • Document upload — Test uploading license and insurance documents
  • Push notifications — Confirm ride request notifications arrive promptly
  • Location accuracy — Verify the driver's position updates smoothly on the map
Tip

To test the full ride flow, run both the User App and Driver App on separate emulators or devices connected to the same backend. This allows you to simulate a complete ride from booking to completion.
