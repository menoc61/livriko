Version Update

This guide covers how to update your Livriko backend and mobile apps when a new version is released.

Pre-Update Checklist

Before updating Livriko, complete the following preparation steps:

Backup Database

Create a full backup of your database using mysqldump or the Laravel Backup package. See Database Upgrade for detailed backup procedures.

Note Current Version

Record your current Livriko version. Check composer.json or the admin panel for version information.

Enable Maintenance Mode

Put the application in maintenance mode to prevent user access during the update:

php artisan down

Updating the Backend

Follow these steps to update the Laravel backend:

# 1. Pull the latest changes from GitHub
git pull origin main

# 2. Install updated PHP dependencies
composer install --no-dev --optimize-autoloader

# 3. Install updated JavaScript dependencies (if frontend changes)
npm install

# 4. Build frontend assets (if needed)
npm run build

# 5. Run database migrations for new schema changes
php artisan migrate --force

# 6. Clear all cached configuration
php artisan config:clear
php artisan cache:clear
php artisan route:clear
php artisan view:clear
php artisan event:clear

# 7. Disable maintenance mode
php artisan up
Note

Always create a backup of your database and files before updating. See Database Upgrade for backup procedures.

Updating Mobile Apps

To update the User or Driver mobile apps:

# 1. Pull the latest changes from GitHub
git pull origin main

# 2. Install updated JavaScript dependencies
npm install

# 3. Update the version number in build.gradle (Android)
# Navigate to android/app/build.gradle and update:
#   versionCode (increment by 1)
#   versionName (e.g., "1.1.0")

# 4. Rebuild the app

# Android:
cd android && ./gradlew clean && cd ..
npx react-native run-android

# iOS:
cd ios && pod install && cd ..
npx react-native run-ios

Post-Update Verification

After updating, verify that everything works correctly:

Check Verification Method
Admin panel loads Visit your admin URL and log in
API endpoints respond Test key endpoints: curl https://your-domain.com/api/v1/health
Database migrations applied Run php artisan migrate:status to verify all migrations are up to date
Queue workers running Check with php artisan queue:status
Email sending works Send a test email from the admin panel
Push notifications work Send a test notification to a device
Mobile apps compile Build and run both User and Driver apps

Handling Merge Conflicts

If you've made custom modifications, you may encounter merge conflicts during git pull:

# Check for conflicts
git status

# If there are conflicts, resolve them manually
# Edit the conflicting files and choose the correct version

# After resolving conflicts
git add .
git commit -m "Resolved merge conflicts after update"

# Continue with the update steps
Important

Always review the changelog or release notes before updating. Some updates may include breaking changes that require additional configuration steps.

Updating Mobile Apps for App Stores

After updating the mobile app code, you need to rebuild and publish to the app stores:

Update Version Numbers

Increment the version code and name in both Android (build.gradle) and iOS (Info.plist) projects.

Build Release Version

Build the release APK/AAB for Android or archive the iOS project in Xcode.

Submit to Stores

Upload the build to Google Play Console and App Store Connect. Follow the store-specific submission guidelines.

Wait for Review

Google Play review typically takes 1–3 days. App Store review takes 1–7 days. Plan your updates accordingly.

Rollback Procedure

If the update causes issues, follow these steps to rollback:

# 1. Enable maintenance mode
php artisan down

# 2. Revert to the previous version
git checkout v1.0.0  # Replace with your previous version tag

# 3. Install dependencies for that version
composer install --no-dev --optimize-autoloader

# 4. Restore the database backup
mysql -u root -p livriko < pre_upgrade_backup.sql

# 5. Clear caches
php artisan config:clear
php artisan cache:clear
php artisan route:clear
php artisan view:clear

# 6. Disable maintenance mode
php artisan up

Using Git Tags for Version Management

Use Git tags to mark release versions. This makes it easy to reference specific versions and roll back if needed:

# Tag a release
git tag -a v1.1.0 -m "Release version 1.1.0"
git push origin v1.1.0

# View all tags
git tag -l

# Checkout a specific tag
git checkout v1.1.0

# Create a new branch from a tag
git checkout -b hotfix/v1.1.1 v1.1.0

Keeping Docs in Sync

If you are maintaining custom documentation for your deployment, ensure you update the documentation files alongside code changes. This prevents discrepancies between the docs and the actual behavior.

Best Practice

Always update your documentation when making configuration changes or adding new features. This helps your team troubleshoot issues and onboard new members efficiently.
