Firestore Collections

Cloud Firestore is the real-time database used by Livriko to store and sync data between the admin panel, User app, and Driver app.

Key Collections

Livriko uses the following Firestore collections:

Collection Purpose Key Fields
riders Rider profile data, FCM tokens, and account status uid, name, email, phone, fcmToken, status
drivers Driver profile data, vehicle info, FCM tokens, online/offline status uid, name, email, vehicleType, fcmToken, status, rating
rides Ride request details, status, fare information, and trip data riderId, driverId, status, pickup, dropoff, fare, distance
locations Real-time GPS coordinates for active drivers driverId, geopoint, timestamp, heading, speed
messages Chat messages between riders and drivers during active rides rideId, senderId, text, timestamp, read
notifications Push notification payloads to be delivered via FCM userId, title, body, type, read, createdAt

Real-Time Listeners

Livriko uses Firestore's real-time listeners to sync data across the platform:

Listener Collection Used By
Ride status updates rides Rider and Driver apps (real-time ride tracking)
Driver location tracking locations Rider app (live map), Admin panel (driver monitoring)
Chat messages messages Rider and Driver apps (in-ride messaging)
Notification delivery notifications Cloud Functions (auto-send via FCM)

Geopoints for Driver Location

Driver locations are stored as Firestore geopoints for efficient spatial queries:

// Storing a driver location (handled by the Driver app)
const locationRef = firestore.collection('locations').doc(driverId);
await locationRef.set({
  driverId: driverId,
  geopoint: new GeoPoint(latitude, longitude),
  heading: heading,
  speed: speed,
  timestamp: admin.firestore.FieldValue.serverTimestamp(),
});

// Query nearby drivers (handled by the Rider app or admin)
const nearbyDrivers = await firestore.collection('locations')
    .where('geopoint', '>=', new GeoPoint(minLat, minLng))
    .where('geopoint', '<=', new GeoPoint(maxLat, maxLng))
    .get();
Note

Firestore geopoints require composite indexes for efficient range queries. Create the necessary indexes in the Firebase Console under Firestore → Indexes.

Data Relationships

Firestore is a NoSQL database, so relationships are managed through document references and field IDs:

Relationship Method Example
Ride → Rider Reference by UID rides/{rideId}.riderId = riders/{riderId}.uid
Ride → Driver Reference by UID rides/{rideId}.driverId = drivers/{driverId}.uid
Message → Ride Reference by rideId messages/{msgId}.rideId = rides/{rideId}
Location → Driver Reference by driverId locations/{locId}.driverId = drivers/{driverId}.uid

Querying Patterns

// Get all active rides for a rider
const rides = await firestore.collection('rides')
    .where('riderId', '==', currentUserId)
    .where('status', 'in', ['requested', 'accepted', 'in_progress'])
    .orderBy('createdAt', 'desc')
    .limit(20)
    .get();

// Get online drivers of a specific vehicle type
const drivers = await firestore.collection('drivers')
    .where('status', '==', 'online')
    .where('vehicleType', '==', 'sedan')
    .get();

// Get unread notifications for a user
const notifications = await firestore.collection('notifications')
    .where('userId', '==', currentUserId)
    .where('read', '==', false)
    .orderBy('createdAt', 'desc')
    .get();

Indexing Requirements

Firestore requires indexes for compound queries. Common indexes needed by Livriko:

Collection Index Fields Query Type
rides riderId + status Get rider's active rides
rides driverId + status Get driver's active rides
drivers status + vehicleType Find available drivers by type
notifications userId + read Get unread notifications
messages rideId + timestamp Get chat history for a ride
Warning

Always back up your Firestore data before making changes to collections or security rules. Data loss in Firestore is irreversible. Use the Firebase console's export feature or the Firebase CLI for backups.
