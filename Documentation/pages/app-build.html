Build APK / AAB

This guide covers building Android APK and AAB files from the Livriko React Native apps. Choose the build type based on your deployment target.

Build Types Overview

Android supports multiple build types. The type you choose depends on how you plan to distribute the app.

Type Command Use Case
Debug APK cd android && ./gradlew assembleDebug Development and testing on devices
Release APK cd android && ./gradlew assembleRelease Direct installation (sideloading), APK distribution
Release AAB cd android && ./gradlew bundleRelease Google Play Store submission (required since August 2021)

Debug Build

Debug builds are unsigned and include development tools. Use them during development and testing only.

# Navigate to the app directory
cd Taxido_user    # or Taxido_driver

# Clean previous builds
cd android
./gradlew clean

# Build debug APK
./gradlew assembleDebug

# Output location:
# android/app/build/outputs/apk/debug/app-debug.apk

Debug vs Release

Debug builds are larger, slower, and not suitable for distribution. They include the React Native Dev Menu and debugging tools. Always use release builds for production.

Release APK Build

Build a signed release APK for direct distribution or sideloading. This produces a single APK file that can be installed on any Android device.

# Navigate to the Android directory
cd Taxido_user/android    # or Taxido_driver/android

# Build release APK
./gradlew assembleRelease

# Output location:
# android/app/build/outputs/apk/release/app-release.apk

Signing Required

You must configure a keystore signing config before building a release APK. Without it, the build will fail. See the signing configuration section below.

Release AAB Build (Google Play)

Google Play Store requires AAB (Android App Bundle) format since August 2021. AAB files are smaller because Google Play generates optimized APKs for each device configuration.

# Build release AAB
./gradlew bundleRelease

# Output location:
# android/app/build/outputs/bundle/release/app-release.aab

Google Play AAB Requirement

Google Play no longer accepts new APK submissions. All new app updates must be uploaded as AAB files. Existing APK-based apps can continue receiving APK updates, but new apps must use AAB.

Keystore Generation

A keystore is a cryptographic file used to sign your Android app. You need it for all release builds. Generate one before your first release.

# Generate a new keystore
keytool -genkeypair -v -storetype PKCS12 \
  -keystore your-keystore.jks \
  -keyalg RSA -keysize 2048 \
  -validity 10000 \
  -alias your-key-alias

# You will be prompted for:
# - Keystore password
# - Your name, organization, city, state, country code
# - Key password (can be same as keystore password)

Never Lose Your Keystore!

If you lose the keystore used to sign your app, you cannot update the app on Google Play. You will have to publish a brand-new app with a different package name, losing all your users and reviews. Store your keystore securely and maintain multiple backups.

Signing Configuration

Configure release signing in android/app/build.gradle for both apps:

android {
    signingConfigs {
        release {
            storeFile file('your-keystore.jks')
            storePassword 'your-store-password'
            keyAlias 'your-key-alias'
            keyPassword 'your-key-password'
        }
    }

    buildTypes {
        release {
            signingConfig signingConfigs.release
            minifyEnabled true
            shrinkResources true
            proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'),
                          'proguard-rules.pro'
        }
    }
}

Secure Your Credentials

Never commit keystore passwords to version control. Use environment variables or a local keystore.properties file that is added to .gitignore.

Version Management

Update the app version before each release in android/app/build.gradle:

android {
    defaultConfig {
        versionCode 1          // Increment for each release (integer)
        versionName "1.0.0"    // Semantic versioning (user-visible)
    }
}
Field Purpose Example
versionCode Internal integer, incremented each release. Google Play uses this to determine update order. 1, 2, 3, 4...
versionName User-visible version string displayed in the Play Store and app settings. 1.0.0, 1.1.0, 2.0.0

ProGuard / R8 Optimization

ProGuard (or R8 in newer AGP versions) shrinks and obfuscates your release build, reducing APK size and protecting source code. The Livriko apps include a ProGuard configuration file.

# android/app/proguard-rules.pro
# Add custom ProGuard rules here

# Keep React Native classes
-keep class com.facebook.react.** { *; }
-keep class com.facebook.hermes.** { *; }

# Keep Google Maps classes
-keep class com.google.android.gms.maps.** { *; }

CI/CD Pipeline

For automated builds, configure a CI/CD pipeline using GitHub Actions, Bitrise, or Codemagic. A basic GitHub Actions workflow:

# .github/workflows/build-android.yml
name: Build Android
on:
  push:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          distribution: 'zulu'
          java-version: '17'
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: cd Taxido_user && npm install
      - run: cd Taxido_user/android && ./gradlew assembleRelease
      - uses: actions/upload-artifact@v4
        with:
          name: app-release
          path: Taxido_user/android/app/build/outputs/apk/release/

Build Complete

Once built, install the APK on a device to test, or upload the AAB to Google Play Console for review and release. See iOS Build for Apple App Store deployment.
