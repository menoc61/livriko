Languages

Livriko supports full multi-language localization for both the mobile apps and the admin panel. Configure languages to match your operational regions and provide a native experience to every user.

How Multi-Language Works

Livriko uses a language system that covers every user-facing string in the platform.

The platform language system is divided into three layers:

  • Admin Panel: The Laravel admin backend uses translation files in resources/lang/. Each language has its own directory with PHP translation arrays.
  • Mobile App (Rider & Driver): The React Native apps use JSON-based translation files located in src/utils/locales/. Each language is a separate JSON file with key-value pairs.
  • Database Content: Vehicle types, service names, and other admin-managed content can have per-language translations stored directly in the database.
Language selection

Users select their preferred language during onboarding or from the app settings. The language choice is saved per user and persists across sessions. The admin panel language is set independently by each admin user.

Adding a New Language

Follow these steps to add a new language to your Livriko platform.

Step 1: Add Language in Admin Panel

Open the Languages page

Log in to the admin panel and navigate to Settings → Languages.

Click "Add New Language"

Click the Add New button at the top of the languages list.

Fill in language details

Enter the following fields:

Field Description Example
Name Human-readable language name displayed in the language picker French, Arabic
Code ISO 639-1 language code (two letters). Must be unique. fr, ar, sw
Direction LTR for left-to-right scripts, RTL for right-to-left scripts LTR (French), RTL (Arabic)
Status Toggle to enable or disable the language for end users Enabled / Disabled

Click "Save"

The language entry is created in the database. It will now appear in the language list with a "Disabled" status until you translate the content.

Step 2: Translate Mobile App Strings

The React Native mobile apps store translations as JSON files. To add a new language:

  1. Copy an existing language file (e.g., src/utils/locales/en.json) and rename it to your new language code (e.g., sw.json for Swahili).
  2. Open the new JSON file and translate each value. Keep the keys identical across all language files.
  3. Register the new language in the app's language configuration file (src/utils/languages.js).
  4. Test the translation by switching the app language in Settings.
// Example: src/utils/locales/sw.json
{
  "welcome": "Karibu",
  "book_ride": "Weka Gari",
  "payment": "Malipo",
  "wallet": "Mkoba",
  "settings": "Mipangilio"
}

Step 3: Translate Admin Panel Strings

The Laravel admin backend uses PHP translation arrays:

  1. Create a new directory under resources/lang/ with the language code (e.g., resources/lang/sw/).
  2. Copy all PHP files from resources/lang/en/ into the new directory.
  3. Translate each array value while keeping the keys identical.
  4. Clear the config cache: php artisan config:clear.

Step 4: Translate Database Content

Vehicle types, services, and other admin-managed content can have per-language names. In the admin panel:

  • When editing a Vehicle Type, you will see translation fields for each enabled language.
  • Enter the translated name for each language. If a translation is left empty, the default language value is displayed.

RTL Language Support

Livriko fully supports right-to-left (RTL) languages like Arabic, Hebrew, and Urdu.

When a language with direction: RTL is selected, the following adjustments are made automatically:

  • Layout Mirroring: The entire app layout is mirrored. The sidebar moves from left to right, text alignment flips, and navigation arrows reverse.
  • Map Direction: The map interface adjusts the pickup/destination markers for RTL reading order.
  • Font Rendering: The app uses RTL-compatible fonts (e.g., Noto Sans Arabic) for proper character shaping and ligature rendering.
  • Number Display: Numbers remain in LTR format even within RTL text, as per the Unicode Bidirectional Algorithm.
  • Admin Panel: The admin panel also supports RTL when the admin user switches to an RTL language.
RTL font requirements

Make sure the appropriate RTL font is bundled with your app. For Arabic, include a font that supports Arabic character shaping (e.g., Noto Sans Arabic or Cairo). The default React Native fonts may not render Arabic correctly.

Editing & Deleting Languages

Editing a Language

  1. Go to Settings → Languages in the admin panel.
  2. Click on the language name or the Edit button.
  3. Modify the name, code, direction, or status as needed.
  4. Click Save to apply changes.

Deleting a Language

  1. Go to Settings → Languages.
  2. Click the Delete button next to the language.
  3. Confirm the deletion in the dialog.
Cannot delete the default language

The language marked as "Default" cannot be deleted. You must first set a different language as the default before deleting the current one. The default language serves as the fallback for any untranslated strings.

Translation Best Practices

  • Complete one language first: Fully translate and test the primary language before adding more. An incomplete translation degrades the user experience.
  • Use professional translation: For production apps, use professional translators or reputable translation services. Machine translation often produces awkward or incorrect phrasing for ride-hailing terminology.
  • Keep keys consistent: All language JSON files must have identical keys. Missing keys will fall back to the default language, which can look jarring.
  • Test RTL thoroughly: RTL languages require extensive visual testing. Check every screen, modal, and notification in RTL mode before enabling it for users.
  • Update translations with app updates: When adding new features, ensure all language files are updated simultaneously. Missing translations in new features are a common oversight.
  • Consider regional variants: French (France) vs French (Canada), Spanish (Spain) vs Spanish (Mexico) — these may need different translations for currency formats, formality, and terminology.
