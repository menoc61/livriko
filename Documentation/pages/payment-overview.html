Payment Gateways

Livriko supports a wide range of payment gateways to process ride payments, rental fees, delivery charges, and wallet top-ups. This guide covers every supported gateway, how to configure it, and best practices for managing payments on your platform.

Cash Payment

Cash is the default payment method and requires zero configuration. It is always available as a fallback option.

When cash is enabled, riders pay the driver directly at the end of the trip. The driver marks the ride as "Completed - Cash" in the app, and the platform records the transaction. Cash payments work offline and are ideal for markets where digital payments are not yet widespread.

How Cash Works

Rider selects "Cash" at checkout

The rider chooses Cash as the payment method before confirming the ride.

Ride is completed

The driver drops off the rider and taps "Complete Ride" in the driver app.

Driver confirms cash collection

The driver enters the amount received and confirms the cash payment.

Platform records the transaction

The fare is logged in the admin panel. The driver's earnings include the cash amount minus the platform commission.

Configuring Cash in Admin

  1. Navigate to Settings → General
  2. Scroll to the Payment Settings section
  3. Toggle Cash to enabled (it is on by default)
  4. Optionally set Cash as the default payment method
  5. Click Save
Cash is always available

Even if you disable Cash in settings, drivers can still collect cash as a fallback. The toggle only controls whether Cash appears as an option in the rider app checkout screen.

Stripe Integration

Stripe is the most widely supported gateway, available in 46+ countries. It supports credit cards, debit cards, Apple Pay, Google Pay, and local payment methods.

Step-by-Step Stripe Setup

Create a Stripe account

Visit stripe.com/register and create a business account. Complete the verification process for your country.

Get your API keys

In the Stripe Dashboard, go to Developers → API Keys. You will see your test keys by default. Copy the Publishable Key (starts with pk_test_) and the Secret Key (starts with sk_test_).

Set up Webhooks

Go to Developers → Webhooks and add a new endpoint. Set the URL to https://yourdomain.com/api/stripe/webhook. Select events: payment_intent.succeeded, payment_intent.payment_failed, and charge.refunded. Copy the Webhook Signing Secret (starts with whsec_).

Configure .env file

Add the Stripe keys to your Laravel .env file:

# Stripe Configuration
STRIPE_KEY=YOUR_STRIPE_KEY
STRIPE_SECRET=YOUR_STRIPE_SECRET_KEY
STRIPE_WEBHOOK_SECRET=YOUR_STRIPE_WEBHOOK_KEY

Enter keys in Admin Panel

Go to Payment Settings → Stripe in the admin panel. Paste the Publishable Key, Secret Key, and Webhook Secret. Toggle Stripe to Enabled.

Test in Sandbox

Use Stripe's test card number XXXX XXXX XXXX XXXX with any future expiry date and any CVC. Process a test ride and verify the payment appears in the Stripe Dashboard under Payments.

Switch to Live Mode

Once testing is complete, toggle the Stripe Dashboard to Live mode. Generate new live API keys and update your .env and admin panel with the live credentials (prefixed with pk_live_ and sk_live_).

Stripe Setting Description Example
Publishable Key Public key for client-side card tokenization pk_test_51abc...
Secret Key Private key for server-side charges (never expose in client code) sk_test_51abc...
Webhook Secret Used to verify that webhook events genuinely come from Stripe whsec_abc123...
Never commit live keys to Git

Always store Stripe Secret Keys and Webhook Secrets in your .env file, which should be listed in .gitignore. Exposing a live Secret Key can lead to unauthorized charges on your account.

PayPal Integration

PayPal is available in 200+ countries and supports PayPal balance, bank accounts, and credit/debit cards through the PayPal wallet.

PayPal Developer Setup

Create a PayPal Business account

Go to paypal.com/business and sign up for a Business account if you do not already have one.

Access the Developer Dashboard

Visit developer.paypal.com/dashboard and log in with your Business account credentials.

Create a REST API App

Under My Apps & Credentials, click Create App. Name it (e.g., "Livriko Production") and click Create App.

Copy Client ID and Secret

Under the Sandbox tab, copy the Client ID and Secret. For production, switch to the Live tab and copy those credentials instead.

Configure in Livriko Admin

Go to Payment Settings → PayPal. Paste the Client ID and Secret, set the mode to Sandbox for testing, and toggle to Enabled.

PayPal Setting Description
Business Email The email address associated with your PayPal Business account
Client ID REST API Client ID from the Developer Dashboard
Secret REST API Secret (keep this confidential)
Mode Sandbox for testing or Live for production transactions
Sandbox vs Live credentials

PayPal Sandbox and Live environments use completely different Client IDs and Secrets. Using Sandbox credentials in Live mode (or vice versa) will cause payment failures. Always double-check which mode you are configuring.

Razorpay Integration

Razorpay is the leading payment gateway for India, supporting UPI, credit/debit cards, net banking, and popular wallets like PhonePe, Google Pay, and Paytm.

Razorpay Setup

Create a Razorpay account

Sign up at razorpay.com and complete your KYC verification as a business.

Get API Keys

Go to Settings → API Keys in the Razorpay Dashboard. Generate a new key pair. Copy the Key ID and Key Secret.

Configure Webhook

Set up a webhook URL at https://yourdomain.com/api/razorpay/webhook for events like payment.authorized and payment.captured.

Enter keys in Admin Panel

Go to Payment Settings → Razorpay. Paste the Key ID and Key Secret. Toggle Razorpay to Enabled.

# Razorpay Configuration
RAZORPAY_KEY=rzp_test_xxxxxxxxxxxxxxxxxx
RAZORPAY_SECRET=xxxxxxxxxxxxxxxxxxxxxxxx
Razorpay Test Mode

Razorpay test keys always start with rzp_test_ and live keys with rzp_live_. Use the Razorpay test cards and UPI IDs from their testing guide to simulate payments.

In-App Wallet System

Livriko includes a built-in digital wallet that allows riders and drivers to store credit, receive refunds, and pay for rides without an external payment gateway.

The wallet system is a core feature of the platform and operates independently from external payment gateways. Here is how it works:

  • Top-Up: Riders can add money to their wallet using any enabled online payment gateway (Stripe, PayPal, Razorpay, etc.).
  • Auto-Deduction: When a rider pays with the wallet, the fare is deducted automatically upon ride completion.
  • Refunds: When a ride is cancelled, the refund amount is credited back to the rider's wallet instantly.
  • Driver Wallet: Drivers have a separate wallet for receiving earnings. They can transfer funds to their bank account or use wallet credit for platform fees.
  • Transaction History: Both riders and drivers can view their complete wallet transaction history in the app.
  • Minimum Balance: You can configure a minimum wallet balance requirement for drivers.
Wallet + Payment Gateways work together

When both Wallet and an online payment gateway are enabled, the rider sees both options at checkout. If the wallet balance is insufficient, the rider can either top up or choose the payment gateway instead.

For detailed wallet configuration including commission settings, withdrawal limits, and fleet wallet management, see the Wallet Management page.

Security Best Practices

Payment security is critical. Follow these guidelines to protect your platform and your users.

Never store card details directly

Livriko uses tokenization through payment gateways. Card details are never stored on your server. All card data is handled by Stripe, PayPal, or Razorpay's secure infrastructure.

  • Always use HTTPS: All payment pages and API endpoints must be served over HTTPS. Configure SSL/TLS on your server before enabling online payments.
  • Keep API keys secret: Store all gateway keys in the .env file. Never hardcode keys in source code or expose them in client-side JavaScript.
  • Verify webhooks: Always validate webhook signatures using the webhook secret provided by each gateway. This prevents spoofed payment confirmations.
  • Use test mode first: Process at least 20-30 test transactions before going live. Verify amounts, receipts, and refund flows.
  • Monitor transactions: Check the Stripe/PayPal dashboard daily for failed payments, disputes, and unusual activity.
  • Enable 3D Secure: For Stripe, enable Strong Customer Authentication (SCA) to comply with European PSD2 regulations.

Common Payment Issues

Solutions for frequently encountered payment gateway problems.

Issue Likely Cause Solution
Payment fails immediately Incorrect API keys or wrong mode (test vs live) Double-check keys match the mode. Regenerate keys if needed.
Webhook not received URL misconfigured or firewall blocking Verify webhook URL in gateway dashboard. Check server logs for 4xx/5xx errors.
Payment successful but ride not updated Webhook signature verification failing Ensure STRIPE_WEBHOOK_SECRET matches the webhook endpoint secret.
Currency mismatch Gateway account currency differs from platform currency Ensure your Stripe/PayPal account supports the currency set in Currencies.
Wallet balance not deducting Wallet feature disabled or cache issue Enable Wallet in admin settings. Run php artisan cache:clear.
