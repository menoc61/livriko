SOS Emergency Feature

The SOS feature provides a critical safety mechanism for both riders and drivers. When activated, it immediately shares the user's real-time location with emergency contacts, displays local emergency numbers, and alerts the platform administrator. This feature is essential for building trust and ensuring user safety in any ride-hailing platform.

How the SOS Flow Works

Step-by-step walkthrough of the emergency alert sequence.

SOS Activation Sequence

  1. Button press — The rider or driver presses the SOS button in the app. A confirmation dialog appears to prevent accidental activation.
  2. Confirmation — The user confirms the emergency by tapping "Yes, Send SOS" or cancels to abort. Some implementations use a long-press (3 seconds) to reduce false alarms.
  3. Location sharing begins — The user's real-time GPS location starts streaming to pre-configured emergency contacts and the admin panel.
  4. Emergency contacts notified — SMS and/or push notifications are sent to the user's emergency contacts with the user's name, current location (with map link), and trip details.
  5. Admin alert — An alert notification appears in the admin panel with the user's identity, location, trip details, and driver information.
  6. Live location tracking — The admin and emergency contacts can view the user's live location on a map as they move. This continues until the SOS is deactivated or the trip ends.
  7. Emergency number displayed — The app displays the configured emergency number (e.g., 112, 911) with a one-tap dial button.

SOS Button Location in the App

  • Rider app — The SOS button is prominently displayed during an active ride, typically on the trip tracking screen.
  • Driver app — The SOS button is accessible from the trip screen and the main dashboard for use even when not on a trip.

Configuring SOS Settings

Follow these steps to set up the emergency SOS feature.

1. Navigate to SOS Settings

Log in to the admin panel. Go to Livriko Management → SOS. You will see the SOS configuration form with all available settings.

2. Set Emergency Number

Enter the local emergency services number for your operating country. Common examples: 112 (Europe), 911 (US/Canada), 999 (UK), 15 (France). This number is displayed to users with a one-tap dial button.

3. Set Support Number

Enter your platform's support hotline number. This is a secondary number displayed alongside the emergency number for non-emergency situations requiring immediate platform assistance.

4. Enable SOS Button

Toggle the SOS button on or off. When disabled, the SOS button is hidden from both rider and driver apps. Keep this enabled in production environments.

5. Add Emergency Alert Contacts

Add phone numbers that will receive SOS alert notifications. These can be platform administrators, safety team members, or trusted contacts. Multiple numbers can be added.

6. Save Configuration

Click Save to apply the SOS settings. The changes take effect immediately in the apps.

Emergency Contacts

How emergency contacts are managed and notified.

Platform-Level Contacts

Emergency contacts configured in the admin panel are notified for every SOS activation across the platform. These are typically:

  • Safety team members — Dedicated staff trained to handle emergency situations.
  • Platform administrators — Senior staff who can coordinate with local authorities.
  • On-call managers — Managers responsible for after-hours emergency response.

User-Level Contacts

In addition to platform-level contacts, riders and drivers can add their own emergency contacts in the app settings. These personal contacts are notified only when that specific user activates SOS.

Notification Channels
SOS alerts are sent via multiple channels simultaneously: SMS (to phone numbers), push notifications (to admin panel), and email (if configured). This redundancy ensures alerts reach the right people even if one channel fails.

Auto-Alert Features

Automated safety features that complement manual SOS activation.

Route Deviation Alert

Automatically sends an alert if the driver deviates significantly from the planned route. Riders can confirm it is okay or trigger an SOS.

Stalled Trip Alert

Detects when a trip is paused for an unusually long time without movement. Sends a check-in notification to the rider to confirm safety.

Live Location Sharing

When SOS is active, real-time GPS location is continuously shared with emergency contacts and the admin panel until the situation is resolved.

Trip Sharing

SOS alerts include full trip details: pickup location, destination, driver name, vehicle details, and license plate for quick identification.

Safety Tips

Best practices for implementing and promoting the SOS feature.

Test Regularly
Test the SOS feature at least monthly to ensure all notification channels are working correctly. Verify that SMS messages are delivered, push notifications arrive, and admin alerts appear in real-time.

Implementation Best Practices

  • Keep the SOS button prominent — Do not hide it behind menus or require multiple taps. In an emergency, every second counts.
  • Use a confirmation step — A single confirmation dialog prevents accidental SOS activations while keeping the process fast.
  • 24/7 monitoring — Ensure someone is always available to respond to SOS alerts. An unanswered alert erodes user trust.
  • Match the emergency number — Verify the configured emergency number is correct for every country you operate in. Wrong numbers can be dangerous.
  • Train your team — Safety team members should know how to respond to SOS alerts, coordinate with authorities, and follow up with affected users.

Promoting Safety

  • In-app education — Show a brief explanation of the SOS feature during onboarding or in the app help section.
  • Pre-ride safety tips — Display safety reminders before each ride (e.g., "Verify driver name and vehicle before entering").
  • Post-ride check-in — Send a quick "How was your ride?" notification after each trip to catch any issues early.
  • Driver verification — Ensure all drivers are thoroughly verified (license, background check, vehicle inspection) before they can accept rides.
